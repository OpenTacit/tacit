# Governance

OpenTacit has one maintainer. This document sets out the current decision and
review process.

## Who decides

The maintainer listed in [MAINTAINERS](MAINTAINERS) decides what merges, what
ships, and what the project is for. There is no committee, no vote, and no
appeal beyond a conversation.

## What that means for you

This has three practical effects.

**Your change may wait.** One person handles reviews. If a pull request has had
no response for two weeks, post a reminder on the thread.

**Design conversations happen before the effort.** [CONTRIBUTING.md](CONTRIBUTING.md)
lists the changes worth opening an issue about first: new capture surfaces,
anything affecting what leaves a member's machine, and schema or wire-contract
changes. Discussing these changes first can prevent work on a change the
maintainer will not accept.

**You keep your copyright.** There is no CLA, and the project holds no right to
relicense your work. That is deliberate and it is not a decision one maintainer
can quietly reverse: Apache-2.0 without a CLA means the code cannot be taken
closed, whoever ends up holding the repository.

## Conduct

[CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md) is the Contributor Covenant 2.1. It
uses "community leaders" in the plural, so its introduction explains that this
project has one maintainer. This does not change its standards.

## How this changes

If the project gains maintainers, this file will define how someone becomes a
maintainer, how disagreements are resolved, and what happens when the original
maintainer stops. Those processes do not yet exist.

Until then, the succession plan is the licence. Apache-2.0 means a fork is
always available to anyone who needs one, and nothing here can be withdrawn
from the people already using it.

## The name is separate

The licence covers the code but does not grant rights to the name. See
[TRADEMARK.md](TRADEMARK.md), which explains what you may do with it without
asking.

## Contact

questions this file does not answer.
